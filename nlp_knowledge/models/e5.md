## The idea

E5 = "EmbEddings from bidirectional Encoder rEpresentations". Trained with weak
supervision on large text-pair corpora plus supervised contrastive fine-tuning.
Its defining convention is **mandatory input prefixes**.

## The prefix rule — the whole reason this file exists

```python
# Asymmetric (retrieval): DIFFERENT prefixes per side
queries   = [f"query: {q}"   for q in queries]
passages  = [f"passage: {p}" for p in passages]

# Symmetric (STS, dedup): SAME prefix both sides
texts = [f"query: {t}" for t in texts]
```

Omitting the prefixes, or using `query:` on both sides of a retrieval task,
degrades quality **with no error and no warning**. This is the most common E5
mistake. The `-instruct` variants take a natural-language instruction on the
query side instead; check which variant you have.

## Family (approximate, `[UNVERIFIED]`)

| Model | Dim | Notes |
|---|---|---|
| `intfloat/e5-small-v2` | 384 | fast, CPU-plausible |
| `intfloat/e5-base-v2` | 768 | solid default |
| `intfloat/e5-large-v2` | 1024 | stronger, slower |
| `intfloat/multilingual-e5-{small,base,large}` | 384/768/1024 | **~100 languages** |
| `intfloat/multilingual-e5-large-instruct` | 1024 | instruction-conditioned |
| `intfloat/e5-mistral-7b-instruct` | 4096 | LLM-scale; heavy |

Typical `max_seq_length` is 512 for the non-LLM variants — verify, and chunk
accordingly.

## When to choose E5

- **Asymmetric retrieval** — this is what it is built for.
- **Multilingual data** — the `multilingual-e5-*` line is the main reason to
  reach for this family. Directly addresses the failure documented in
  `SimonLaub/NLP_JobTrend` `[VERIFIED]`, where a monolingual English encoder was
  applied to Danish and the author observed the quality drop firsthand.
- When you want mean pooling + normalization with no surprises.

## When not to

- CPU-only at scale (even `small` is slow over a large corpus).
- When BM25 already saturates the metric — check first.
- When you cannot reproduce the prefix convention at inference time (e.g. a
  pipeline that loses the query/passage distinction).

## Checklist

1. Confirm the exact prefix strings on the model card.
2. `normalize_embeddings=True`; cosine = inner product.
3. Mean pooling (library default handles it).
4. Confirm `max_seq_length`; chunk longer documents with overlap.
5. Mine hard negatives **with the same prefixes** you deploy.
6. Compare against BM25 and against the hybrid — not just against nothing.
